# ADR-0010 — Terraform, not CDK; one root module, two tfvars; apply from a laptop if GitHub cannot reach the bank's account

Status: Accepted
Date: 2026-09-03

## Context

The deployment target is an AWS sandbox that IDBI provisions, whose IAM posture we do not
control. The infrastructure is about twenty resources. The people who will review it are a bank
network and security team, for whom the plan output is the review artefact. We should not assume
that a GitHub-hosted workflow will be allowed to assume a role in the bank's account.

## Decision

`infra/terraform` with `vpc`, `rds`, `ecs`, `alb`, `cdn`, `secrets`, `observability` and `budget`
files and `envs/{team-sandbox,idbi-sandbox}.tfvars`; `deploy.yml` on `workflow_dispatch` with
OIDC when the account allows it; the runbook in `infra/terraform/README.md` documents the
ten-step laptop apply.

## Alternatives

- CDK. Needs a Node toolchain and `cdk bootstrap` IAM in a bank account.
- Six Terraform modules. Over-structured for about twenty resources.

## Consequences

HCL a bank network team reads; `terraform plan` is the review artefact; we apply `team-sandbox`
first so `idbi-sandbox` is a redeploy.
