# ADR-0011 — No model anywhere in this build; three tiers; pgvector extension present, memory feature deferred

Status: Accepted
Date: 2026-09-03

## Context

The invariant that matters most is that the model never decides suitability. The avatar provider
already brings a model with it, gated by the `check_suitability` tool. Adding a second model for
the text fallback would add a provider key, an egress route, DPDP exposure and a heuristic
post-check on the compliance path, and would create a class of demo failure (rate limits,
outages, hallucinated figures) that the deterministic engine cannot have. The semantic-memory
feature from the archived prototype needs an embedding store, but its embedding dimension depends
on a model that has not been chosen.

## Decision

Tier 0 live avatar → Tier 1 deterministic text (`core/query.ts`, `core/suitability.ts`) → Tier 2
badged offline simulation. No LLM phrasing tier, no embeddings. Migration 0001 creates the
`vector` extension so the deferred memory adapter needs no infrastructure change; no memories
table ships.

## Alternatives

- An LLM text advisor with a post-check. A provider key, egress, DPDP exposure and a heuristic on
  the compliance path.
- A memories table with a pre-chosen embedding dimension.

## Consequences

The compliance and egress story is clean (Runway and LiveKit are the only external calls); a
whole class of demo failure is removed; the model-API egress lines in
`docs/integration/aws-sandbox.md` are superseded.
