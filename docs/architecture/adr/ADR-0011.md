# ADR-0011 — No model anywhere in this build; three tiers; pgvector extension present, memory feature deferred

Status: Accepted · amended 2026-09-20 (see Amendment)
Date: 2026-09-03

## Context

The invariant that matters most is that the model never decides suitability. The avatar provider
already brings a model with it, gated by the `check_suitability` tool. Adding a second model for
the text fallback would add a provider key, an egress route, DPDP exposure and a heuristic
post-check on the compliance path, and would create a class of demo failure (rate limits,
outages, hallucinated figures) that the deterministic engine cannot have. The semantic-memory
feature from the archived prototype needs an embedding store, but its embedding dimension depends
on a model that has not been chosen.

## Decision

Tier 0 live avatar → Tier 1 deterministic text (`core/query.ts`, `core/suitability.ts`) → Tier 2
badged offline simulation. No LLM phrasing tier, no embeddings. Migration 0001 creates the
`vector` extension so the deferred memory adapter needs no infrastructure change; no memories
table ships.

## Alternatives

- An LLM text advisor with a post-check. A provider key, egress, DPDP exposure and a heuristic on
  the compliance path.
- A memories table with a pre-chosen embedding dimension.

## Consequences

The compliance and egress story is clean (Runway and LiveKit are the only external calls); a
whole class of demo failure is removed; the model-API egress lines in
`docs/integration/aws-sandbox.md` are superseded.

## Amendment — 2026-09-20

**Tier 2 is gone. There are two tiers, not three.** The badged offline simulation was the
`offline/` chunk inside `apps/web`, and `apps/web` has been deleted from the repository — see the
amendment on [ADR-0001](ADR-0001.md), which is where that removal is recorded. Nothing replaced
it: `apps/mobile` renders what the API returns and has no engine of its own to fall back to.

The ladder as it now runs is **Tier 0 live avatar → Tier 1 deterministic text**
(`core/query.ts`, `core/suitability.ts`), and Tier 1 is the floor. That is a narrower ladder and
the same decision. Every word of the Decision above that matters here is about what is *not* in
the build — no LLM phrasing tier, no embeddings, no second model on the compliance path — and
losing the tier below the deterministic engine removes a fallback, not a model. The invariant the
Context calls the one that matters most, that the model never decides suitability, is untouched:
it was always the `check_suitability` gate that held it, at Tier 0, and Tier 2 never ran a model
at all.

Two things follow that a reader should not have to discover:

- The Consequences above still hold and one of them is now cheaper to state. "A whole class of
  demo failure is removed" was written about model outages; with Tier 2 gone, an API the client
  cannot reach is no longer a labelled local simulation but a plain error, which is a failure mode
  ADR-0001's amendment records rather than one this decision introduced.
- `meta.tier` on the wire is still `z.enum(['server', 'offline'])`
  (`packages/contracts/src/domain.ts:1233`) while `AdvisoryService` only ever writes `'server'`
  (`apps/api/src/application/advisory.service.ts:364`). The `'offline'` member is the last
  structural trace of Tier 2 and no longer has a producer. Narrowing it is a contract change with
  a client of its own and is not made here.

Migration 0001 and the `vector` extension are unaffected: the memory feature is deferred for the
reason given above — the embedding dimension still depends on a model nobody has chosen — and no
memories table ships.
