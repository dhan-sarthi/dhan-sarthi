# ADR-0008 — Opaque bearer sessions, 30-day sliding, with a HostIdentityPort seam for GO Mobile+

Status: Accepted · amended 2026-09-20 (see Amendment)
Date: 2026-09-03

## Context

During the review window the "customer" is whichever synthetic persona a reviewer picks; there is
no real login, and there must not be one that pretends to be. Each reviewer still needs an
isolated session with its own clock, decisions and record, returning to it a week later on the
same phone. In Phase 2 the app runs inside GO Mobile+, which will hand the WebView some host
token whose format is not yet known.

## Decision

`POST /sessions` issues a 256-bit opaque token stored as its sha256; sessions expire after 30
days idle; the persona picker is the demo's authentication. `HostIdentityPort.exchange(hostToken)`
is the named Phase-2 seam with a `NotImplemented` adapter and a WebView integration note.

## Alternatives

- JWTs. Key management for no benefit at one task sitting next to Postgres.
- 24-hour expiry. Too short for a two-week review.
- Building the SSO exchange now. The host token format is unknown.

## Consequences

Revocable, one lookup; a reviewer returning next week keeps their record; "how does this know who
the customer is inside our app" has a one-file answer.

## Amendment — 2026-09-20

`HostIdentityPort` has been deleted (`apps/api/src/ports/host-identity.port.ts`). The interface
never had an adapter: `NotImplementedHostIdentity`, named in the Decision above and in the port's
own doc comment, was never written, no file imported the type, it was absent from `Deps`, and
`composition/root.ts` never named it. An interface nobody implements and nobody calls is not a
seam — it is this ADR restated in TypeScript, with nothing to stop the two drifting apart, which
is how the architecture document came to assert an adapter that does not exist.

The decision itself is unchanged: opaque bearer sessions, 30-day sliding expiry, the persona
picker as the review window's authentication, and a host-token exchange as the Phase-2 path into
GO Mobile+. This ADR is where that intention belongs while the token format is unknown, and it
should become its only record.

It is now. The five files outside this one that still described `HostIdentityPort` as something
that exists were corrected on 20 September 2026, each keeping the Phase-2 intention and pointing
here for it rather than naming a type, a signature or an adapter:

- `docs/architecture/HLD.md` — the C4 diagram's GO Mobile+ node now reads "host-token exchange
  (ADR-0008, not built)"; the source tree's `ports/` listing no longer carries
  `host-identity.port.ts`; and the `### HostIdentityPort (stub)` section — an
  `exchange(hostToken)` signature, an adapter `NotImplementedHostIdentity` that was never
  written, and a citation of `docs/integration/go-mobile-plus.md` that was never written either
  — is replaced by `### There is no host-identity port`, which says what happened and why the
  interface returns only with its first adapter.
- `docs/architecture/DATA-AND-API.md` — both mentions. The `GET /api/v1/customers` row now
  attributes its 503 to an empty `listCustomers()`, which is what raises it; the sessions
  section calls the Phase-2 path a host-token exchange and a plan.
- `docs/architecture/BUILD-PLAN.md` — the Day 6 row is a record of what a day was meant to
  deliver and is left exactly as adopted. A new `## Notes on the record` section after the table
  says that the `go-mobile-plus.md` / `HostIdentityPort` half of it was never delivered.
- `docs/product/destination.md` — the Phase-2 sentence now names the difference between the two
  configurations (who says which customer this is) instead of a type.
- `packages/contracts/src/routes/customers.ts` — the one that shipped. The route summary read
  "Disabled (503) under a host-identity adapter"; it now reads "503 when the source has no
  pickable customers", which is what `SessionService.pickable()` actually does. No test pinned
  the old string, and the OpenAPI document is generated at boot, so nothing else had to move.

One drift named above outlives this amendment and is not part of it: the `## Ports` catalogue in
`HLD.md` documents nine ports where `apps/api/src/ports/` has sixteen. That is seven ports with
no entry, which is the opposite failure to this one — a document behind the code rather than
ahead of it — and wants a pass over the catalogue, not a line edit here.

The interface returns with its first adapter, in one change: when IDBI supplies the token format,
the port and the exchange land together, `POST /api/v1/sessions` takes a host token instead of a
cif, and `GET /api/v1/customers` answers 503 — the behaviour the picker already has when
`listCustomers()` comes back empty, which now lives in `SessionService.pickable()`
(`apps/api/src/application/session.service.ts`).
