# ADR-0012 — Seed 42 months (24 history + 18 forward) at anchor 2026-09-01; seed is a one-off task, never on boot

Status: Accepted
Date: 2026-09-03

## Context

The simulated clock is the product's way of showing time-dependent behaviour in seconds: a loan
clearing, a salary arriving, a goal drifting. With the ledger in Postgres, advancing the clock
must reveal rows that already exist rather than generate new ones, so two reviewers on the same
customer see identical months. That means the seed has to cover the furthest date the clock can
reach. Loading the seed also needs the migration role, which the runtime task must not hold.

## Decision

`pnpm seed` writes anchor−23 → anchor+18 months via `toSeedBundle`; the memory adapter calls the
same function; the seed refuses to run while sessions exist unless `--force`; in AWS it is
`aws ecs run-task` with a separate task definition, not the container entrypoint.

## Alternatives

- 48 forward months. More than the clock UI reaches; doubles the rows for nothing.
- Migrate and seed on every container boot. Admin credentials in the runtime task and a race
  under rolling deploys.

## Consequences

The clock has 18 months of headroom; the runtime task holds only `dhan_app`; drift is a CI
failure via `--check`.
