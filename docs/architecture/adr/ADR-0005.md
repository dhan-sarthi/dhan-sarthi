# ADR-0005 — Plain SQL migrations and pg; no ORM

Status: Accepted
Date: 2026-09-03

## Context

The schema is small (about twenty tables), it carries compliance properties that are easiest to
express directly in SQL (revoked privileges, raising triggers, unique constraints that double as
idempotency guards), and the people most likely to read it are bank engineers who read SQL every
day. Two data-shape bugs are specific to this domain: money must be a number exactly once, and a
`date` that becomes a JavaScript `Date` shifts by a day when it crosses a timezone, which is how
the 1st becomes the 31st.

## Decision

Numbered `.sql` files applied by a runner of about forty lines; SQL in template strings inside the
postgres adapters; `pg` type parsers set once (`NUMERIC` → number, `DATE` → `'YYYY-MM-DD'`
string).

## Alternatives

Prisma, Drizzle or Kysely.

## Consequences

A bank reviewer reads SQL directly; the schema is small; the `DATE` parser prevents the
timezone-shifts-the-date bug.
