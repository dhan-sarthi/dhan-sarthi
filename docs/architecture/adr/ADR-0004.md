# ADR-0004 — One persistent Fargate task; the RPC host is the horizontal-scaling boundary

Status: Accepted
Date: 2026-09-03

## Context

The suitability gate on the avatar path is a `backend_rpc` tool: our process joins the LiveKit
room as a hidden participant and holds that connection for the life of the call. A held
connection rules out request-scoped compute, and it means the process that opened a call is the
only one that can answer its tool calls. Everything else the API does is stateless. The
deployment has to make the one stateful thing explicit rather than pretend the service scales
like a plain web tier.

## Decision

ECS Fargate, `desired_count` 1, private subnet, rolling deploy at min 100 % / max 200 % with a
120-second SIGTERM drain. Leases and the minute budget live in Postgres with an atomic claim;
leases carry `task_id` so any task can mark a lease released and the owning task's reaper closes
its handle.

## Alternatives

- Lambda. Impossible: the LiveKit participant is a held connection.
- EC2. Kept as the `infra/ec2-compose` hedge for a sandbox that grants only a t3.medium.
- N tasks with session affinity. Documented, not built.

## Consequences

A deploy during a live call ends it gracefully; more avatar concurrency means more Runway
credentials, not more tasks; the constraint is written down rather than hidden.
