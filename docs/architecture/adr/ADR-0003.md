# ADR-0003 — Ports and adapters with a composition root; three BankDataPort adapters

Status: Accepted
Date: 2026-09-03

## Context

The product has to run in four situations with the same application code: against seeded
Postgres for the demo, against in-memory data for tests and for a laptop with no database,
against IDBI's sandbox APIs when they arrive, and with or without the avatar provider configured.
Branching on environment variables inside services would spread those situations through every
file; a single store interface, as the archived prototype had, would force every situation to
implement everything.

## Decision

`apps/api/src/ports` contains interfaces only; `adapters/{postgres,memory,idbi-sandbox,runway,null}`
implement them; `composition/root.ts` is the only file naming concrete classes; `BANK_SOURCE` and
`AVATAR_PROVIDER` select adapters at boot; one shared contract suite runs against every adapter of
a port.

## Alternatives

- A single `Store` interface, as in the prototype.
- A dependency-injection framework.
- Branching on environment inside services.

## Consequences

IDBI's feed is a mapping edit plus a fixture swap; the no-database and no-keys modes are
configurations; dependency-cruiser rules make the layering a CI failure rather than a README
promise.
