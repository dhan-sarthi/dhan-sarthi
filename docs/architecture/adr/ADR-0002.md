# ADR-0002 — As-of arithmetic lives in packages/core/src/asof.ts, used by the generator and every adapter

Status: Accepted
Date: 2026-09-03

## Context

The generator in `packages/fixtures` computes a customer's facts as of a date inside
`generateCustomerFile`: account aggregates from month-end balances, a liability's remaining
tenure and outstanding principal, a SIP's accumulated instalments. Once the ledger lives in
Postgres and is read back as of the session's clock, the same arithmetic has to run over rows
instead of over the generator's in-memory streams. If two implementations exist, the API and the
generator will disagree by a rupee somewhere, and every number on a slide becomes suspect.

## Decision

`accountFactsAsOf`, `liabilityAsOf` and `sipHoldingAsOf` are pure functions in `packages/core`.
`generateCustomerFile` calls them (behaviour unchanged; the 54 existing tests are the regression
guard) and `PostgresBankData`, `InMemoryBankData` and the composite adapter call the same
functions.

## Alternatives

- `packages/fixtures/src/asof.ts`. This puts the synthetic-data package in the API's production
  dependency graph.
- Re-implement the aggregates as SQL window queries. Two implementations reconciled only by a
  parity test.

## Consequences

Parity is by construction; there is one module to read; the generator change is a refactor
covered by existing tests and done on Day 2 with the parity test as the safety net.
